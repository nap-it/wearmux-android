# WearMux Android v1.0.0 — Initial research release

Initial research release of the WearMux Android hub and Wear OS companion, accompanying *WearMux: Real-Time Multimodal Sensing and Feedback across Heterogeneous Wearables*.

The phone provides a common acquisition and feedback interface for compatible wearables and its own sensors. Device adapters expose sensing and output capabilities to modality-specific modules, while applications consume observations locally or through configured remote services. This is the Android host described in the manuscript's architecture and outdoor pedestrian-assistance demonstrations.

## Included capabilities

- Connect compatible smartglasses, wristbands, insoles, camera devices, and Wear OS watches through BLE, Wi-Fi, and the Wear OS Data Layer.
- Collect camera, microphone, inertial, heart-rate, and location data where supported by the connected hardware.
- Run selected vision, activity, and audio processing locally, with optional remote processing through configured application endpoints.
- Deliver audio feedback, vibration, and watch alerts.
- Monitor and record data, and expose observations through HTTP, WebSocket, and optional MQTT integration.

## Downloads and installation

- `wearmux-phone-v1.0.0.apk`: Android 14+ (API 34), `arm64-v8a` phone.
- `wearmux-wear-v1.0.0.apk`: Wear OS watch with API 34+, compatible with `armeabi-v7a`.
- `SHA256SUMS`: checksums for both signed APKs.

Install the phone APK on the phone and the companion APK on its paired watch. Watch communication uses the Wear OS Data Layer through the phone. The phone and watch APKs share a package ID and signing certificate.

Remote features require reachable services configured in the app; the compiled default server address belongs to the development setup. Remote voice commands require the compatible Sherpa keyword-spotting service. The Navisens trajectory view is optional and requires a developer key supplied at build time.

The package ID is `com.wearmux.android`. Older `com.example.peciwearables` installations are separate apps and do not update in place. Installing a signed release over a debug build of the same package may require uninstalling the debug build first, which removes its local data.

## Research scope

Capabilities depend on compatible hardware, firmware, permissions, and network conditions. This release provides the Android host and watch companion; [WearMux Headless](https://github.com/nap-it/wearmux-headless) is maintained and released separately.
